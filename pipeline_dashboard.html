Pipeline Architecture & Overview

This preprocessing pipeline is optimised for 128-channel BioSemi EEG recordings across multiple predefined experimental paradigms from the ALS Centre Utrecht, UMC Utrecht. Considering that the data collection protocol and equipment are almost identical between the ALS Centre Utrecht and Dublin, the pipeline is suitable for use with datasets from both centres. Incorporating other experimental paradigms or recording equipment into this pipeline is straightforward and requires minor work.

Supported Experimental Paradigms

RS (Resting-State)

Resting-state eyes-open and eyes-closed recordings. Typically three 2-minute blocks for each condition, totalling 12 minutes.

MMN (Cognitive task)

Mismatch Negativity, a varaint of the passive auditory oddball paradigm. Typically three blocks of 7-8 minutes, totalling 21-24 minutes.

SART (Cognitive task)

Sustained Attention to Response Task, a variant of the Go/No-Go cognitive task. Typically three blocks of 5-6 minutes, totalling 15-18 minutes.

MT (Motor task)

MotorMarker, a motor paradigm using a right-hand pinch grip movement (simultaneous EEG and EMG data). Processes MT2 and MT3 tasks. Typically one 7-8 minute block each, totalling 14-16 minutes.

The Four-Script Design

1. preproc_folders.m

Initialises paths, cohorts, task, and visits. Needs editing.

2. preproc_participants.m

Handles participant selection. Needs editing.

3. preproc_parameters.m

Defines preprocessing parameters. Do not edit.

4. preproc_main.m

Executes batch processing loops. May be edited.

Two-Stage Processing Overview

The master script preproc_main.m iterates across selected datasets and executes the pipeline via run_subjects.m in two distinct sequential steps per subject:

Run 1: Continuous data processing

~5-10 min

Covers raw import, high-pass filtering, line noise removal, bad channel detection, artefact attenuation (STAR, GEDAI), channel interpolation, and ICA decomposition.

Triggered in preproc_main.m → run_subjects.m → run_subject_1

Run 2: Epoched data processing

~1 min

Applies low-pass filtering, task-specific epoching, baseline correction, rejection of bad trials, and quality assurance exports.

Triggered in preproc_main.m → run_subjects.m → run_subject_2

Raw Data Structure & Naming

Correct data organisation is critical for automated file discovery. This section outlines the folder hierarchy and naming conventions required for EEG files.

Expected Directory Tree

📁 <rootrawdata>
📁 <group>
📁 T<visit>
📁 <subject_id>
📄 ...Tasks files...
  • <rootrawdata>: Base data folder (e.g. E:\data\raw\)
  • <group>: Study or clinical cohort (e.g. ALS, CONTROL)
  • T<visit>: Session indicator (e.g. T1, T2)
  • <subject_id>: Unique alphanumeric code (e.g. ALS12345, C42)
Example Folder Path: E:\data\raw\ALS\T1\ALS12345\ E:\data\raw\CONTROL\T1\C42\

Expected File Naming

📄 <subject_id>_T<visit>_<task><block>.bdf
  • <subject_id>: Unique alphanumeric code (e.g. ALS12345, C42)
  • T<visit>: Session indicator (e.g. T1, T2)
  • <task><block>: Paradigm and block (e.g. MMN1, SART1, EO1, EC1, MT2)
Example File Name: ALS12345_T1_MMN1.bdf

Note on Resting-State Processing

Data from eyes-open (EO) and eyes-closed (EC) conditions should ideally be kept in the same folder and processed together. The aggregate duration should reach approximately 12 minutes to provide sufficient data for stable ICA decomposition.

Configuration & Participant Selection

Set up dataset paths in preproc_folders.m and define participant queues in preproc_participants.m.

myPaths Configuration (preproc_folders.m)

Field Type/Example Description
mycodes 'E:\matlab\preprocessing_pipeline' Absolute path to your repository containing the pipeline code.
rootrawdata 'E:\data\raw' Absolute path to the base folder holding raw EEG datasets, structured by clinical group and visit.
rootpreproc 'E:\data\preprocessed' Absolute path to the destination folder where output files will be written.
task 'MMN' Defines the experimental paradigm to be processed.
group {'ALS', 'CONTROL'} Defines the cohort(s) to be processed. Accepts a cell array with one or more cohort labels.
subgroup 'AFM_C9ORF72' or '' An optional selector used in conjunction with Table 1 to isolate specific subgroups (e.g. C9orf72 or SOD1 mutation carriers). Leave as an empty string ('') if no subgroup filtering is required (designed for Utrecht datasets).
visit 1 or 1:5 A numeric scalar or array specifying the longitudinal visit indices.
table1 'E:\matlab\preprocessing_pipeline\files\tables\FULL_CLINICAL_TABLE_2026-08-14.txt' Absolute path to Table 1 exported from R. Required only if myPaths.subgroup is used (designed for Utrecht datasets).

Participant Selection Methods

Select which method to use by editing preproc_participants.m. This is done manually by commenting or uncommenting relevant sections within the function. Click each method below to expand its configuration details.

Method A: Automatically Load All Participants in Folder Standard
Click to toggle

For standard processing where every recording present in the targeted group and visit directory should be analysed:

% Discover all participant recordings in the raw data folder
myPathsOut.subjects = list_participants(myPathsOut.rawdata, {});
Method B: Automated Clinical Database Selection (select_relevant) Database
Click to toggle

Designed for Utrecht clinical datasets. This method cross-references files found on disk with records in myPaths.table1 to include only participants meeting predefined diagnostic criteria:

% 1. Discover all recordings in the raw directory myPathsOut.subjects = list_participants(myPathsOut.rawdata, {}); % 2. Filter against clinical records in Table 1 myPathsOut.subjects = select_relevant(myPathsOut.subjects, myPathsOut);

The select_relevant helper matches detected directory IDs against Table 1 based on clinical diagnosis and genetic status:

  • 'ALS': ALS diagnosis and subtype (excluding PMA).
  • 'CONTROL': Healthy control participants.
  • 'AFM_C9ORF72': Asymptomatic family members carrying C9orf72 repeat expansions.
  • 'AFM_ARPP21': Asymptomatic family members carrying ARPP21 mutations.
  • 'MND_C9ORF72': Motor neurone disease patients with C9orf72 mutations.
  • 'MND_SOD1': Motor neurone disease patients from the pre-saved list_sod1_als.mat list.
Method C: Manual Subject Selection Manual
Click to toggle

When only specific participants need to be analysed or re-run, use the explicit participant list override:

% Explicit single participant myPathsOut.subjects = {'ALS12345'}; % Or load a predefined .mat list: % load('E:\matlab\preprocessing_pipeline\files\lists\list_c9_als.mat', 'list_als'); % myPathsOut.subjects = list_als;

Pipeline Execution

Batch runs are initiated via preproc_main.m. Complete the pre-flight checks and choose between cohort batch processing and multi-task pipeline verification.

✅ Checklist

  1. Start MATLAB (R2021a or newer, verified on R2025b).
  2. Navigate to pipeline root directory.
  3. Verify search path: ensure EEGLAB/FieldTrip are not present on the path prior to initialisation.
  4. Configure preproc_folders.m settings (paths, task, cohorts, visits).
  5. Configure preproc_participants.m selection method (Method A, B, or C).
  6. Execute sections within preproc_main.m.

Note on Figures: To suppress figure pop-ups during batch execution, set cfg.figure.visible = 'off' in preproc_parameters.m.

Execution Loops

Loop A: Cohort Batch Processing (Default)

Iterates through every group and visit defined in myPaths.


							for i_group = 1:length(myPaths.group)
							for i_visit = 1:length(myPaths.visit)
							myPathsTmp = preproc_participants(i_group, i_visit, myPaths);
							[errorLog, listFailed{i_group, i_visit}] = run_subjects(myPathsTmp, errorLog);
							end
							end

Loop B: Multi-Task Batch Processing (Testing)

Executes paradigms sequentially for a single group/visit index.

list_tasks = {'MMN', 'SART', 'RS', 'MT'};
							for i_task = 1:length(list_tasks)
							myPaths.task = list_tasks{i_task};
							myPathsTmp = preproc_participants(i_group, i_visit, myPaths);
							[errorLog, listFailed{i_task, i_visit}] = run_subjects(myPathsTmp, errorLog);
						end

Automated Error Tracking

If an individual dataset encounters an exception, run_subjects catches it without terminating the overnight batch queue.

1. Structured Log

These errors are captured in the errorLog array (group, visit, subject, index, step, message).

2. Command Window

The log is printed as a summary report upon batch completion.

3. Export

The log is also saved: <myPaths.rootpreproc>/overnight_pipeline_errors.csv
